一念：Android AI 闪念胶囊
产品、架构与技术选型方案 v0.4
更新日期：2026-10-12

文档状态：产品设计与选型建议，尚未实施正式 Android 客户端。
本次修订依据：优先 Android；其他客户端暂不开发；参考成熟任务管理产品与开源组件；现代简约 UI；先提供可交互页面预览。
暂用名称：“一念”。名称与品牌尚未最终确定。

============================================================
1. 产品定位与范围
============================================================

产品定位：以语音闪念为入口，帮助个人把想法转化为行动，并持续调整安排的垂直 Agent。

核心闭环：随手记录 → 整理或挑战 → 形成候选行动 → 安排时间 → 执行与反馈 → 回顾调整。

主要价值：
1）记录时少操作：打开就能说，没想清楚也可以保存。
2）规划时少纠结：知道什么重要、什么被阻塞、本周能做多少。
3）执行时有下一步：提供少量有理由的建议，允许跳过、休息和放弃。
4）管理权属于用户：手动、语音、AI 和外部 Agent 的修改可查看、可追溯、可撤销。

首发仅开发 Android 客户端。iOS、Web、Windows、macOS 客户端不进入当前范围。
当前 preview/ 内的 HTML 是 UI 评审工具，不代表要开发 Web 产品。
服务端仍提供 API / MCP，以便外部 Agent 使用；它不是额外的用户客户端。

差异化来自长期维护的事项状态、可靠的排期与修改规则、个人节奏，以及方法与实际行动之间的闭环。方法包用于增强效果，不作为唯一壁垒。

2. 产品参考与借鉴方向
============================================================

Todoist
- 参考：快速添加、清晰任务列表、优先级、标签、子任务和过滤视图。
- 采用：安静的列表、少量重点、录入后再组织。
- 调整：让语音收集、原始想法、候选行动成为一等对象。
- 来源：https://www.todoist.com/features

TickTick / 滴答清单
- 参考：任务、日历、专注计时及多视图之间的衔接。
- 采用：任务可以直接开始专注；日期与清单共享同一事项。
- 调整：首版不叠加习惯打卡、团队协作等模块。
- 来源：https://ticktick.com/features

Structured
- 参考：手机上的单日可视化时间线。
- 采用：任务块和空闲时间同时可见，以一天为默认展示单位。
- 调整：新增语音闪念、依赖关系与 AI 变更提案。
- 来源：https://structured.app/

这些产品作为功能和交互参考，不复制其品牌、截图、图标或专有代码。

3. 核心设计原则
============================================================

3.1 想法、任务、安排分离
- 想法可以长期只是想法，不要求安排日期或完成。
- 任务表达一个行动及完成标准。
- 安排表示为这个任务分配的一段时间；一个任务可以有多个安排。
- “想做”“也许”“有空试试”默认保留为想法或候选行动，不能自动制造承诺。

3.2 原文、推测、确认分离
- 保留原始转写及其版本，允许回听和修正。
- 标明 AI 推测的标签、日期、耗时等字段。
- 用户明确设定或修改的值不能被后续异步 AI 结果静默覆盖。
- 音频保留期限可配置；删除记录时同步处理派生摘要与索引。

3.3 记录优先于整理
- 文字与录音先可靠落盘；转写、分类和规划可以异步。
- 网络或模型失败不影响原始内容保留。
- 只在歧义影响实际修改时追问，不把每次记录变成表单。

3.4 用户安排的稳定性
- 固定事项、正在执行的事项、近期安排受到保护。
- 重排考虑切换成本与移动成本，不因一条闪念重排整个星期。
- 排不下时明确报告容量不足，让用户选择推迟、缩小范围或放弃。

3.5 休息与自主权
- 休息、空闲和放弃是合法结果。
- 不把看视频直接判为分心，不凭应用打开时长判定任务完成。
- 用户反馈优先于系统对精力和状态的猜测。

4. 主要功能
============================================================

4.1 闪念输入
- 主动语音录入、文字录入；后续接入 Android 分享菜单和快捷入口。
- 一段长口述允许包含多个想法、待办、问题与情绪表达。
- 保存音频、转写、来源、时间、处理状态；支持中断恢复和失败重试。
- 首版采用“录音 → 转写 → 结构化整理”；持续实时语音对话后置。

4.2 整理模式
- 目标：理清结构、保留观点、识别可执行事项与待澄清问题。
- 输出：摘要、要点、候选行动、相关事项、推测字段。
- 默认先保存；按自动化偏好决定是否直接应用低影响的分类操作。
- 合并或去重保留来源；不能静默吞掉看似相似但不同的想法。

4.3 Argue / 挑战模式
- 目标：检查关键假设、提出有价值的反例、比较替代方案。
- 输出：关键假设、分歧、暂定判断、下一步验证。
- 可设置轻度追问或深度挑战；设置轮次/预算与结束条件。
- 允许保留分歧，不以说服用户为目标。
- 方法包示例：决策比较、事前失败分析、最小实验、任务拆解。

4.4 事项管理
- 类型：想法、任务、项目/集合、等待条件。
- 任务字段：标题、说明、完成标准、状态、用户优先级、预估耗时、领域、项目、日期。
- 关系：父子从属、前置依赖、相关、来源。
- 依赖采用有向无环图；检查循环、自依赖和失效引用。
- 外部等待支持“等回复”“等某日期”，不强制伪装成另一条任务。
- 重复任务按规则生成实例；编辑单次和修改规则要分开。

4.5 多视图
- 现在：一项主要建议、少量替代项、推荐理由、开始专注。
- 闪念：按时间和领域回看；搜索、筛选、原文、来源。
- 优先级：对同一批任务分组和排序。
- 计划：周条 + 单日时间线；周总量用于评估容量。
- 依赖：先展示局部前后关系，复杂图后置。
- 所有视图引用同一份领域数据，通过同一命令服务修改。

4.6 时间与偏好初始化
- 设置工作日、工作时段、个人时间、专注偏好、免打扰。
- “工作/个人”是领域；“沉浸/碎片”是方式，两者可以组合。
- 默认配置可立即开始使用，复杂偏好渐进补充。
- 支持例外日期、临时空闲、时区变化；详细配置后续逐步增加。

4.7 规划与当前行动推荐
- 输入：可用时间、依赖、任务优先级、截止压力、耗时、场景、用户反馈。
- 输出：可行候选、推荐顺序、计划草案、冲突和未安排原因。
- 展示推荐理由；可以换一个、暂缓、今天不做或休息。
- 用户优先级和 AI 推荐分数分开保存。

4.8 执行与回顾
- 专注开始、暂停、中断、结束；计时不等于任务完成。
- 任务可以部分完成，再次安排剩余工作。
- 提醒按渠道和时段设置；支持稍后提醒、失效取消和去重。
- tips 简短且针对当前行动；语音播报为可选功能，避免公共场合自动出声。
- 回顾关注未完成原因、估时偏差、推荐是否有用，不单纯追求完成数量。

5. Android 信息架构与视觉
============================================================

UI 风格已于 2026-10-14 确认：采用 v4“氧气淡绿 · 轻盈浮层”作为一念默认 UI 设计与全局视觉基准。
完整规范见项目根目录《UI设计规范.txt》，包括配色、字阶、卡片、导航、语音入口、阴影、动效与深色模式。
固定参考截图存放于 design/reference/。后续页面沿用该规范。

底部四个入口：现在 / 闪念 / 计划 / 我的。
语音入口位于底部导航上方，便于单手操作；复杂编辑放入详情页或底部弹层。

现在：日期与当前时段 → 单一推荐事项 → 接下来列表 → 闪念入口。
闪念：时间线 / 优先级 / 依赖切换 → 过滤与搜索 → 原话与相关事项。
计划：周条选日期 → 单日时间线 → 未安排事项和建议排期。
我的：工作时间、个人时间、专注时长、自动化程度、通知与数据设置。

视觉方向：清透的氧气淡绿，用薄表面边缘、左上方受光和分层投影形成柔和立体感。
- 底色：薄荷白 #F2F8F5；主要表面：透白 #FCFFFD。
- 正文：深绿 #2E4238；次要文字：灰绿 #5F7368。
- 强调色：#3D6F58；推荐表面：浅绿 #E2F0E8。
- 主按钮：淡绿渐变 #C0E0CD 至 #AFCFBF，深绿文字 #294B39。
- 辅助色：生活与时间使用浅蓝 #E9F1F7；挑战记录使用浅粉 #F7EAEE。
- 原生字体与中文无衬线字体，保持清楚的标题、任务和辅助信息层级。
- 推荐卡、闪念卡采用薄底边与分层投影；后续任务共享较低层级的透白表面。
- 闪念记录按来源、标题、原文摘要、分类和模式分层排列；整张卡片进入详情。
- 视图和周日期使用浅凹槽，选中控件轻浮起；分类筛选显示真实数量。
- 语音入口采用深绿色实体胶囊；导航保持透白，弹层有明确的实色表面与投影。
- 按下时表面降低并收紧阴影；悬停轻抬，视图指示器滑动；遵从减少动态效果设置。
- 深色模式使用松绿色表面与浅绿强调；正式实现需检查对比度、字体缩放、TalkBack、触控目标和返回手势。
- 后续页面、组件与原生实现默认遵循《UI设计规范.txt》和 v4 固定参考。

预览实现范围：
- 已制作浏览器可交互原型，数据仅保存在当前浏览器。
- 可体验四个页面、任务编辑/完成/撤销、依赖解锁、计时、工作时间配置。
- 可体验示例语音、整理/挑战模式、保存闪念、示例计划应用与撤销。
- AI、语音转写、排期为明确标注的演示，没有接入真实模型或设备权限。
- 原型不包含正式 Android 原生组件集成和真机验证。
- 浏览器检查已通过：Argue 保存、专注暂停、依赖解锁、编辑与撤销、空日程、应用安排、偏好保存与持久化。320/360/412 像素宽度下四个页面无横向溢出；检查过程中未出现页面脚本错误。

6. 开源组件与完整系统候选
============================================================

6.1 推荐复用：Compose Material 3
- 定位：导航、底部弹层、输入、按钮、选择、状态与无障碍语义。
- 许可：AndroidX 组件采用 Apache 2.0；正式集成时核对所选 artifact。
- 使用方式：自定义颜色、字阶和形状，避免未经设计地拼默认控件。
- 来源：https://developer.android.com/develop/ui/compose/designsystems/material3

6.2 推荐复用：Kizitonwose Calendar
- 定位：日历、周条、月历、日期选择；支持自定义日期单元格。
- 许可：MIT。
- 边界：不是完整按小时排布的日程控件，也不提供业务排期优化。
- 日程时间块、重叠处理、跨时段分配和依赖约束仍需实现。
- 来源：https://github.com/kizitonwose/Calendar

6.3 推荐复用：Calvin-LL / Reorderable
- 定位：Compose 列表和网格拖动排序。
- 许可：Apache 2.0。
- 用于优先级、子任务手动排序；提供上移/下移等 TalkBack 替代操作。
- 不将列表排序直接等同于任务依赖或自动排期。
- 来源：https://github.com/Calvin-LL/Reorderable

6.4 自定义轻量视图
- 时间线：Compose LazyColumn 和自定义布局。
- 局部依赖链：可访问的普通组件；复杂连线才考虑 Canvas 与布局算法。
- 优先级列表：普通列表 + Reorderable。
- 初期无需图数据库，也无需任意第三方 UI 插件运行时。
- FullCalendar、React Flow 属于 Web 技术路线，不作为当前原生客户端依赖。

6.5 研究候选：Tasks.org
- 是完整的任务管理应用，非可直接嵌入的一组视图组件。
- 可研究任务管理与安卓交互实现。
- 仓库标示 GPL-3.0；若整仓复用，需单独处理许可和长期维护路线。
- 当前建议：研究，不作为默认 fork 基座。
- 来源：https://github.com/tasks/tasks

6.6 研究候选：Vikunja
- 是完整任务管理系统，可作为自托管任务后端的候选。
- 主要许可 AGPL-3.0-or-later，桌面目录另有许可。
- 原始语音、Idea、变更提案、用户节奏与 AI 排期仍需额外建模。
- 当前建议：先自建轻量领域服务；只有验证复用收益明显时再评估接入。
- 来源：https://github.com/go-vikunja/vikunja

选型结论：复用原生基础组件，自己掌握核心数据模型与交互。上述库已做文档和许可筛选，尚未固定版本、构建 PoC 或验证实际兼容性。

7. 技术栈与模块架构
============================================================

Android：
- Kotlin。
- Jetpack Compose + Material 3。
- ViewModel + Coroutines + StateFlow 管理页面状态与异步工作。
- Room 保存事项、关系、记录、计划和待同步操作。
- DataStore 保存轻量偏好。
- 应用私有目录保存待上传录音；根据保留策略清理。
- WorkManager 处理可延迟同步与重试，不负责准点提醒。
- 通知和定时提醒按 Android 平台能力单独实现。

服务端：
- TypeScript + Node.js + Fastify，模块化单体。
- PostgreSQL 保存权威同步版本、事项关系、变更记录与计划。
- S3 兼容对象存储保存音频等附件。
- pg-boss + 独立 Worker 承担持久化队列、重试和延迟处理。
- ASR、LLM、TTS 通过独立适配器接入，避免供应商绑定。
- API / MCP 与内部 Agent 共用领域服务、权限和字段校验。

模块边界：
1）Capture：录入、上传、转写、来源追溯。
2）Items：Idea、Task、项目、关系、状态。
3）Planning：时间规则、可行性、排序、时间块、草案。
4）Execution：专注、实际投入、完成反馈。
5）Agent：整理、挑战、候选修改、上下文选择。
6）Notifications：提醒策略、发送、取消、去重。
7）Sync：增量同步、幂等、版本冲突、离线补偿。
8）Integrations：API、MCP、日历及后续平台接口。

调用路径：
Android 手动/语音/AI 入口 → 领域命令 → 本地更新与待同步队列 → 服务端领域服务 → 数据库。
服务端异步队列 → ASR/LLM → 结构化变更提案 → 业务校验 → 记录结果与同步。
外部 Agent → API/MCP → 同一个服务端领域服务。

部署建议：先保持一个业务服务、一个 Worker 进程和一个 PostgreSQL 实例。根据实际负载再拆分，不提前建设微服务。

8. 核心数据模型
============================================================

Capture：原始音频引用、原始转写、修订版本、来源、录入时间、处理状态。
Idea：观点、主题、摘要、用户补充、讨论结论；可以没有任务。
Task：行动、完成标准、状态、用户优先级、耗时估计、领域、计划相关约束。
Relation：contains / depends_on / related_to / derived_from 等关系。
TimePolicy：工作日、可用时段、领域、专注偏好、例外日期。
TimeBlock：任务的时间分配；包含开始、结束、是否固定和计划版本。
Session：实际开始、结束、暂停、中断、投入时间和用户反馈。
ChangeSet：修改主体、原因、来源、基础版本、字段差异、应用状态。
Reminder：触发条件、通知渠道、去重键、有效计划版本、发送状态。
ActivitySignal：后续可选的粗粒度设备信号，包含来源、时间、有效期和可信程度。

字段规则：
- 每个业务对象有稳定 ID、用户归属、版本和时间戳。
- 截止时间、计划时间、提醒时间分开。
- 仅日期、时间范围和精确时刻保留不同语义。
- 存储时区标识；精确时刻标准化；相对日期保留解析依据。
- 用户优先级与推荐评分分开。
- 任务状态与是否阻塞分开；阻塞由依赖或等待条件计算。
- AI 推测与用户确认记录来源；用户固定字段受到保护。
- 删除采用可同步的删除标记，防止旧设备或迟到结果重新创建记录。

============================================================
9. AI 修改、排期与同步规则
============================================================

9.1 统一修改管道
识别目标 → 生成结构化命令或 ChangeSet → 检查权限/版本/依赖/时间 → 按策略应用或预览 → 写审计记录 → 更新提醒与其他视图。

明确的单条修改可以直接应用并提供撤销。歧义明显或影响多个安排时展示范围和差异；不要求用户对每个自动标签逐一确认。

自动化层级：只建议 / 自动整理 / 自动安排未固定事项。用户可以按行为授权。

9.2 推荐与排期
第一步：筛选可做事项，检查依赖、可用时间、设备/地点和硬约束。
第二步：按重要性、截止压力、解锁价值、精力匹配、切换成本和搁置时间排序。
第三步：生成计划，处理拆分、最短专注时长、固定安排、休息和缓冲。
第四步：解释取舍、未安排原因和不确定信息。

初期用确定性的启发式算法，不让 LLM 独自决定和写入日程。LLM 负责理解、候选拆分与解释；更复杂的约束求解后续引入。

9.3 离线与冲突
- Android UI 读取 Room；离线操作显示待同步状态。
- 服务端维护跨入口共享的确认版本。
- 提交携带 operation_id、base_version、actor 和来源。
- 相同 operation_id 重试只应用一次。
- 不同字段可在安全条件下合并；相同字段冲突保留原值和提案，不能静默覆盖。
- 外部 MCP 在手机离线时修改服务端，手机下次同步接收变更；明确存在同步延迟。
- 转写或 AI 结果绑定输入版本；输入已修改或删除时，旧结果不得覆盖或复活对象。
- 队列重试可能重复执行，业务副作用必须幂等。

10. Android 平台约束
============================================================

录音：首版前台主动录音。处理电话、音频焦点、权限拒绝、空间不足和进程中断。后台录音属于独立功能，需要设计前台服务及通知，不预设长期常驻可行。

提醒：已知时间的提醒使用平台通知/定时机制；动态建议由服务端和客户端状态协同。WorkManager 不能承诺准点运行。精确定时的适用性、权限、系统版本与分发渠道需在实现时核对。

使用情况采集：Android UsageStatsManager 通常需要用户到设置页授权。它提供使用统计，不提供用户真实完成某项工作的充分证据。首版默认关闭；先用专注计时、日历与用户反馈验证推荐价值。

分发：暂未决定优先 Google Play、国内应用商店还是直接 APK。该选择影响推送渠道、服务可达性与测试设备，应在进入提醒和发布实施前确定。核心领域和 UI 不依赖此决定。

https://developer.android.com/training/data-storage/room
https://developer.android.com/topic/libraries/architecture/workmanager
https://developer.android.com/reference/android/app/usage/UsageStatsManager

11. API / MCP / Skill
============================================================

API：面向普通程序，提供稳定数据查询、命令、状态及后续事件通知。
MCP：面向外部 Agent，提供结构化 tools / resources。
Skill：说明何时调用哪些能力、如何处理歧义、如何检查和提交计划；它不代替服务端权限。

首批能力建议：
capture.create / items.search / tasks.update / dependencies.add
plan.propose / plan.apply / next_action.get / sessions.record

统一要求：
- 用户范围与权限作用域；本人的工作/个人内容可进一步限制暴露范围。
- 输入输出 schema、幂等键、版本号、修改来源。
- 清楚区分已保存、处理中、失败、需要澄清。
- 批量计划以修改集为单位提交，避免改到一半留下不一致。
- 原始音频和敏感原文不默认暴露给所有外部客户端。
- 外部文档、网页和日历文本只作为数据，不能作为权限或执行指令。
- 普通读写与 AI 推理分别计量，避免外部 Agent 已处理后再次强制付费推理。

12. 主要设计冲突及处理
============================================================

快速记录 vs 信息完整：先保存，在需要执行时才补问。
自动化 vs 控制权：按行为授权，可追溯、可撤销，尊重手动固定。
想法发散 vs 待办压力：Idea 与 Task 分开，候选行动不自动变承诺。
智能重排 vs 稳定性：加入移动成本，保护固定与近期安排。
主动提醒 vs 打扰：预算、冷却、免打扰、跨渠道去重、及时取消旧提醒。
分类能力 vs 标签失控：领域/项目/标签分层，限制自动创造新分类。
多视图 vs 手机可读性：默认四个入口；依赖只展开局部，不缩小桌面图。
个性化 vs 隐私：最少采集、优先本地汇总、提供数据与已学偏好的查看/删除。
完成数量 vs 重要价值：关注重要事项与用户认可，避免总推荐简单小任务。
开放集成 vs 一致性：所有入口共用命令、权限、幂等和版本校验。
云端智能 vs 保密承诺：明确哪些内容发送给模型服务；不得含糊承诺服务端完全不可读。

13. 交付阶段与验收
============================================================

阶段 A：视觉与交互评审（当前）
- 四个主要页面及语音弹层预览。
- 展示任务修改、原文、依赖、计划草案和撤销。
- 决定视觉密度、信息架构和输入模式。
- 交付是原型，不是 APK。

阶段 B：Android 基础闭环
- 原生 Compose 客户端、Room、偏好、主动录音和可靠落盘。
- ASR 与整理/挑战接入，手动与语音修改、简单依赖。
- 现在/闪念/计划视图、基础提醒、账号同步及最小 API/MCP。
- 验收：录音不中途丢失；AI 失败不丢原文；修改跨视图一致；离线重试不重复建任务。

阶段 C：个人规划
- 时间规则、容量估计、固定安排、重复事项、日历集成。
- 推荐与自动排期、专注和回顾。
- 验收：不违反硬约束，不覆盖固定计划，排不下明确说明，旧提醒及时失效。

阶段 D：可选主动辅助
- Android 使用统计信号、方法包、个性化调整、扩展视图。
- 只增加有证据能改善用户体验的感知与自动化。

验证用例重点：
- 模糊日期、否定表达、口误、多事项混说。
- 不同输入版本下的迟到 AI 结果。
- 依赖循环、等待外部条件、删除前置任务、重新打开任务。
- 离线修改与外部 MCP 并发修改。
- 录音中断、进程重建、通知拒绝、弱网和重试。
- 320/360/412 dp 布局、系统大字体、TalkBack、暗色与返回手势。

效果指标：
- 记录后需要修正的比例与耗时。
- 用户找到并开始下一步所需时间。
- 推荐接受、跳过及原因。
- 计划被用户推翻的频率。
- 提醒被忽略、关闭或造成打扰的比例。
- 用户主观规划负担是否降低。
