# 一念 Android V1 开发计划

## 项目目标

把当前产品方案、v4 UI 规范与交互预览落成可安装运行的 Android 原生 V1。V1 先保证个人设备上的记录、组织、计划和执行闭环，采用本地优先实现；不假设尚未确定的模型、语音、云服务商或分发渠道。

## 依据与约束

- 产品范围：[`../产品与技术方案.txt`](../产品与技术方案.txt)，重点参考 Android 信息架构、技术选型、核心数据模型、平台约束和阶段 B。
- 视觉依据：[`../UI设计规范.txt`](../UI设计规范.txt)、[`../AGENTS.md`](../AGENTS.md) 和 `../design/reference/*v4*`。
- 浏览器原型只作为交互参考，不把它包装成 Web 产品；V1 必须是 Kotlin + Jetpack Compose 原生 Android 应用。
- 先做本地数据闭环；云端 AI、账号同步、API/MCP 需要另行确定服务端契约和供应商。
- 目标设备依据现有环境暂定 Android 13 / API 33；最低版本暂定 API 26，开发代理应在项目 README 明确并说明兼容性取舍。

## V1 范围

### 必须交付

1. 可由 Android Studio 打开并可构建 debug APK 的 Kotlin/Compose 项目，附 Gradle Wrapper、清楚的启动说明和权限说明。
2. 四个底部入口：现在、闪念、计划、我的；遵循 v4「氧气淡绿 · 轻盈浮层」规范，适配浅色/深色、系统字体缩放、窗口 Insets 和 TalkBack 基础语义。
3. 本地持久化的 Idea 与 Task：创建、查看、编辑、归档/完成；Idea 可由用户主动转换为 Task，保留来源关系。任务字段至少包含标题、说明、状态、用户优先级、估时、日期/时间和依赖；编辑器暴露显式的完成 / 撤销完成 / 归档 / 删除；完成操作独立于专注计时。
4. 直接在「现在」页通过 "+ 任务" 创建任务，无需先建立闪念。
5. 任务依赖可通过任务编辑器查看、增加和移除前置依赖；自依赖和形成环的依赖由仓储层拒绝并向用户显示原因。
6. 快速文字录入；主动录音并把音频写入应用私有存储，用户可查看和删除。权限拒绝、录音失败或进程重建不得伪报保存成功。暂未选 ASR 服务时明确显示「仅保存录音 / 转写未配置」，不能伪造 AI 结果；我的页 ASR 入口使用状态行而非开关，避免暗示开启即激活。
7. 现在页给出一个有理由的本地下一步建议，可开始/暂停/结束专注计时；暂停和恢复后保留已累计时长，计时本身不自动标记任务完成。
8. 计划页提供周日期切换、单日事项/时间块查看，并允许用户手动安排和移除安排；不覆盖用户已固定的时间块，冲突时明确提示。
9. 我的页保存工作时段、常用专注时长、主题等轻量偏好；关键操作在不同页面共享同一持久化数据源。
10. 有意义的空状态、错误/权限状态与基础示例数据；删除录音或事项时同步清除本地关联文件/关系。

### 本次不交付

- 真实云端 LLM 整理/挑战、自动排期、云端 ASR/TTS。
- 登录、跨设备同步、PostgreSQL/对象存储、服务端 API/MCP/Skill。
- 后台持续录音、应用使用情况采集、日历集成、复杂重复规则、可靠定时推送、商店发布与计费。
- 浏览器预览的再开发或包装。

这些功能依赖方案中尚未确定的服务商、数据区域、分发渠道或详细产品规则；V1 保留干净的接口边界，但不得用假数据伪装成已接通能力。

## 验收标准

- 项目从干净 checkout 按 README 步骤能同步并生成 debug APK。
- 四个入口都能打开，核心按钮有真实行为；页面之间不各自维护互相矛盾的假数据。
- 文本 Idea/Task 与偏好经应用重启仍保留；录音条目可查看、可删除，权限关闭时给出明确恢复路径。
- Idea 转 Task、依赖阻塞、日期安排、专注计时之间的状态关系符合产品方案；计时结束不擅自完成任务。
- 专注时长跨暂停/恢复及进程重建持续累计；固定时间块冲突会说明原因并保留固定块。
- UI 使用 v4 截图/规范中的淡绿配色和浮层层级，窄屏、暗色与字体放大时主要操作仍可用。
- 未配置的模型、转写、同步能力保持明确禁用/未配置状态；不得展示成功假象。
- 自动化 JVM 与设备端 instrumented 测试套件需保持全绿、零 `@Ignore`、零失败、零跳过；本次回归的实际执行结果以 `docs/test-report-v1.md` 为准。

## 自动化测试要求（V1 验证补充）

V1 的核心数据/任务/会话/依赖逻辑必须可被自动化回归。当前实现策略：

- 纯 JVM 单元测试仅覆盖 Android-free 工具类（如 `DateUtil`、`DurationFormatter`），位于 `app/src/test/`。
- 仓储与业务逻辑测试走 instrumented 路径（`androidTest`），用 `AndroidJUnit4` + 真机/模拟器的 `ApplicationProvider` Context；不使用 Robolectric，不下载 Maven 上的 Android `runtime` jar。
- Compose UI 烟测同样跑在 `androidTest`，覆盖底部导航、闪念录入、任务创建、计划页与专注入口的可达性。
- 修复后 V1 的仓储 / UI 测试需保持零 `@Ignore`、零失败、零错误。

**交付验收标准**：在干净 checkout（按 README 步骤全新 clone 并同步
的项目工作树）上执行 README 列出的本地测试命令
（`./gradlew :app:testDebugUnitTest --rerun-tasks` 与
`./gradlew :app:connectedDebugAndroidTest`），JVM 与 instrumented
套件必须全绿，无 `@Ignore`、无失败、无跳过。该标准描述的是
「应在干净 checkout 上能够达成」的目标，并不等同于本次回归已经
在干净 checkout 上跑过。

**本次回归取得的证据**：本次回归并未从零重新 clone，而是在
本仓库当前 `main` 分支的本地工作树上直接执行上述两条命令。结果为
12/12 JVM 单元测试、48/48 设备端 instrumented 测试通过，零
`@Ignore`、零失败、零跳过；详细命令、设备、套件覆盖范围与
有意限制见 `docs/test-report-v1.md`。

## 开发默认值与待后续确认

- 单模块 Android 应用，Kotlin、Jetpack Compose、Material 3、ViewModel/StateFlow、Room、DataStore、Coroutines。
- `minSdk = 26` 暂作 V1 默认；`compileSdk`/`targetSdk` 选本机安装且被所用 Gradle 插件支持的版本，并在 README 记录。
- 音频本地保存；除非现有环境明确支持且可清楚标注，否则不把平台网络识别称为离线/本地 ASR。
- 后续阶段再确定模型与语音供应商、账号与同步契约、提醒渠道、音频留存策略、自动化等级和商店渠道。
