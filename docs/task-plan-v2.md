# 一念 Android V2 开发计划（优先级修订）

## 目标

在 V1 本地 Idea、Task、手动安排与专注数据上完成个人规划阶段。当前优先解决“应用内日历与视图切换”体验；不依赖 Android 系统日历、账号、服务端或语音服务。日历数据完全来自应用本地的任务和时间块。

V1 与 V2 当前基线：公开仓库 `LogicTortoise/yinian-android` 的 `main`；V2 初次发布提交 `16a3c4d`。这是对 V2 后续开发的范围和优先级修订，完成后更新 V2 测试报告。

## 新优先级

1. **P0：去除系统日历依赖**。删除 `READ_CALENDAR` 权限、`CalendarContract` reader、日历授权/启用偏好和设置入口；排期只读取应用本地记录。
2. **P1：应用内日历与视图切换**。提供日、周、月三种视图，前后日期导航、回到今天、视图间保持所选日期；月历点选日期切到日视图，周/日视图能查看并打开本地时间块。月份网格与周起始使用 `java.time`，不接入外部日历库。
3. **P2：可编辑排期草案**。生成后可逐项调整建议时间或移除建议；预览期不写数据库；确认应用时重新检查固定块、冲突、重复应用和正在执行的专注任务。
4. **P3：重复事项可管理**。在界面中编辑/归档重复规则，支持修改单次实例、取消单次实例，并清楚区分“只改本次”与“改规则及未来实例”。
5. **P4：专注回顾与页面可达性**。修复「我的」页无法滚动到底部的问题；实现日/周回顾、实际专注时长、任务估时对比、计划完成率，进行中的计时计入当前时段，跨日会话按日期分摊。
6. **P5：回归、迁移、说明**。覆盖日/周/月切换和日期导航、草案编辑/应用、重复规则编辑、回顾计算和 Room v2→v3→v4 数据保留；更新 README 与测试报告。

语音转写、录音播放/波形不属于本次 V2 完成门槛，继续明确标注为未接入/后续能力。

## 功能范围与验收

### P0 — 本地优先，无系统日历接入

- 清单无 `READ_CALENDAR`、`WRITE_CALENDAR`。
- 移除 `CalendarContract.Instances`、系统日历权限申请、日历授权和启用偏好。
- `YinianRepository` 与 planner 只使用本地 `TaskEntity`、`TimeBlockEntity`、工作规则和专注数据；现有应用日程不因删除系统日历功能而丢失。
- JVM 权限测试验证没有日历权限与 `INTERNET` 权限。

### P1 — 内置日历及视图切换

- 「计划」页提供 `日 / 周 / 月` 视图切换、上一段/下一段导航和「今天」快捷入口。
- 月视图展示完整月份网格、本地时间块标记；点日期进入该日视图。
- 周视图覆盖周一到周日，展示每天的本地时间块数量/安排状态；点日期查看该日。
- 日视图按时间顺序展示本地时间块和空闲时段，支持打开时间块、手动新增/移除时间块。
- 视图切换不丢失所选日期；跨月、闰年、时区/DST 下日期与星期正确。
- 所有查询来自 Room 和 `java.time`，不新增第三方日历依赖。

### P2 — 可编辑草案

- 草案逐条显示任务、建议日期/时间、依据和未安排原因。
- 用户可编辑建议时间、移除单条建议、放弃或应用草案。
- 预览和编辑阶段不写入 `TimeBlockEntity`。
- 应用前重新校验时间范围、固定块/正在进行任务冲突和草案指纹；冲突不产生部分写入；同一草案重复应用幂等。

### P3 — 重复规则与单次实例

- 支持新增、编辑、归档日/工作日/每周规则。
- 修改规则时明确是否同步未来未完成的生成实例；历史实例不被静默改写。
- 生成任务可“仅修改本次”或“取消本次”，不意外修改母规则。
- 按 `(ruleId, dayKey)` 幂等生成，编辑、归档和再次排期不重复生成任务。

### P4 — 回顾与可达性

- 「我的」页可垂直滚动，主要设置、重复事项、回顾入口在窄屏上可见可点。
- 回顾支持日/周切换，展示实际专注分钟、完成数、任务估时对比和计划完成率。
- 活跃专注会话显示累计已暂停时长 + 当前运行段；跨午夜时长按本地日期拆分，不把全部时长记入开始日。
- 放弃会话不计入实际投入；暂停时长不重复计算；空数据展示清楚的空状态。
- 不采集应用使用情况，不使用“分心”等不可验证标签。

### P5 — 兼容与交付

- Room v2→v3→v4 显式迁移保留 Idea、Task、关系、时间块、专注数据；v3→v4 仅新增专注分段表，不做破坏性迁移。
- V1 和 V2 JVM/instrumented 回归全部通过，零跳过/忽略。
- README、权限说明和测试报告描述当前无系统日历集成、内置视图与实际测试范围。
- V2 完成后提交并推送到公开仓库 `main`。

## 不包含

系统日历读取/写入、云端 LLM/ASR、账号同步、API/MCP、可靠后台提醒、应用使用情况采集、复杂约束求解器、语音转写/播放增强、商店发布和计费。当前语音录入保持本地录音并如实说明 ASR 未配置。

## 执行约定

- 所有生产代码开发由 Claude Code 开发子代理负责；自动化测试、测试报告与 README 回归说明由 Claude Code 测试子代理负责。
- 生产代码所有权按文件边界拆分；测试子代理只在开发子代理收尾后开始执行。测试发现生产缺陷时，另开 Claude 开发子代理修复，再由测试子代理回归。
- 控制器负责计划、代码范围审查、证据综合、提交和推送；控制器不直接执行测试命令。
- 使用现有 Compose、Room、DataStore、Coroutines、Java Time；不增加外部日历或大型日历/求解器依赖。
- 每项测试报告记录执行命令、设备/模拟器、通过数、跳过数及覆盖边界。
